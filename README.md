# SakayLokal frontend

## Local development

1. Import `../dbsql/sakaylokal.sql` in phpMyAdmin. If you already imported the earlier schema, run `../dbsql/002_calapan_admin_update.sql`. If the seeded terminals/routes were soft-deleted during testing, run `../dbsql/003_restore_seed_transport_data.sql` to restore them.
2. Import `../dbsql/006_complete_oriental_mindoro_locations.sql` to preload the complete Oriental Mindoro municipality/city and barangay directory from `info_ormin`. For older installations, `005_oriental_mindoro_locations.sql` remains compatible but contains the earlier seed set. Location changes should be made in SQL seed files so every installation has the same master data.
3. Configure the LavaLust environment from `../LavaLust/.env.example`.
4. Start Apache and MySQL in WAMP. The expected API URL is:
   `http://localhost/Finalproject_Transports/LavaLust/public/api`
5. From this folder run:

```powershell
npm install
npm run dev
```

The admin login is `admin` / `admin123`. The admin route redirects to login when no authenticated admin session exists. The dashboard summarizes reports by status, while the Manage Reports page gives administrator accounts report-volume charts for the last 8 weeks, 12 months, or 5 years; staff accounts can review reports without seeing those charts.

Maps use OpenStreetMap street tiles through Leaflet. The terminal directory's **Use my location** action displays the user's current position as a blue dot on the live map and centers the map there while sorting nearby terminals. The browser must allow location access. Interactive terminal and report pickers start centered on the whole Oriental Mindoro province. Since a province-wide map is too zoomed out for accurate street selection, the first click zooms in; click the road again to place the pin. Selections outside the province are rejected: coordinates must fall within the province's geographic bounds, and Nominatim must confirm that the snapped point is in Oriental Mindoro. A selected point is snapped to the nearest mapped drivable road within 80 meters using OSRM's public demo service. The street name comes from that snapped road (not the nearby address returned by reverse geocoding). On the admin terminal form, municipality and barangay are selected automatically when the verified map pin matches the location master data. If reverse geocoding cannot identify a barangay, choose the correct barangay from the form's list; the list is limited to the detected municipality when available, and staff remain limited to their assigned municipality. No API key is required. If OpenStreetMap has no street name for a road, the form identifies it as an unnamed mapped road and shows its nearest locality instead of presenting a road type or nearby street as the selected road. Route detail pages calculate a fresh drivable road path between the route's origin and destination terminal coordinates through OSRM, then draw that returned road geometry on the map; they do not depend on manually entered route points. On a terminal details page, **Get directions** requests the user's current location, calculates a driving route to that terminal with OSRM, and displays the route on the map with distance and estimated drive time. The browser must allow location access; if permission is denied or location services are unavailable, the page displays an explanation. Check the selected pin against the actual road and entrance before saving, since snapping can choose a nearby parallel road and OpenStreetMap coverage varies by area. Public OSRM, Nominatim, and tile servers are rate-limited community services without an uptime guarantee; use them for low-volume development and arrange an appropriate hosted or self-hosted provider before scaling up. The seeded demo terminal coordinates are within Calapan City, Oriental Mindoro.

To point the React app at another API location, create `frontend/.env.local`:

```text
VITE_API_BASE_URL=http://localhost/your-path/LavaLust/public/api
```

Production builds use `https://sakaylocal-backend.onrender.com/api` by default. Set `VITE_API_BASE_URL` in the frontend hosting environment to override it.

The public terminals homepage and terminals page use the same active records returned by `/api/terminals`; this keeps admin changes synchronized with what users see. Users can filter by municipality/city and barangay, and the selected location is stored in the URL as `?city=...&barangay=...` so it survives refresh and can be shared. Terminal creation, route origin/destination selection, public route search, and report location selection all use cascading municipality/city → barangay → terminal choices. The Admin location directory is selection-first instead of rendering the entire province in one long page, while terminal forms use the same SQL-managed locations through dropdowns. If there are no active records, the UI shows an empty state instead of displaying stale demo records.

The admin dashboard's **Print dashboard** button opens the browser's print dialog with navigation and action buttons removed. Dashboard report totals and recent submissions use the lightweight `/api/admin/dashboard` summary endpoint. When a verified terminal pin cannot be matched automatically to a barangay, choose the correct barangay from the form's location list; staff remain limited to their assigned municipality.
